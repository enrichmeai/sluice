# CLAUDE.md

`enrichmeai/sluice`: three small fine-tuned local models (`dbt-bq`, `composer-dag`,
`cloudrun-job`), the data that makes them, the checks that judge them, and the evals that gate
them. Read `README.md` first, then `docs/BUILD_PROMPT.md` (the plan) before any change.

**The decision (owner, 2026-11-02): own the weights, not the runtime.** Ollama runs the models;
Penstock routes, constrains, validates and ships them. No inference code is written here.

## The four rules. They are not negotiable.
1. **Verify before you write.** Every tool, flag, version, model tag, licence or benchmark number
   is checked against its official source before it is used or stated. `docs/BUILD_PROMPT.md`
   marks what is still **[unverified]**; the first session that confirms one removes the mark
   and cites the page. Never write from memory. If the source cannot be read, say the check did
   not run and treat it as a blocker.
2. **Done means green, and green means the validators.** A model's output, a training sample or
   an eval case counts only when the scripts in `validators/` say `pass`. A check that could not
   run is `not_run`, never `pass`. A fine-tune ships only when `evals/report.md` shows it above
   the gate in `docs/BUILD_PROMPT.md` § 6, with the commands and numbers quoted.
3. **Three attempts, then stop.** After 3 failed fix attempts at the same gate, stop changing
   files and write a Blocker summary (what failed, the last error, the last diff) on the issue.
4. **Prove red first.** Every validator has a broken fixture it fails on before a good one it
   passes. Every new rule in a check comes with its red case.

## What never goes in git
- Model weights, GGUFs, adapters, checkpoints (release assets, see penstock#218).
- Table rows, exports of data, anything from a customer project. Schemas and metadata only.
- Any secret or credential. Never post one anywhere on GitHub either.
- Training samples generated by a commercial API (Anthropic, OpenAI, Google): their terms forbid
  training competing models on the output. The teacher is an open-weight model.

## Licences
Apache 2.0 here. A base model, dataset or teacher is used only if its licence allows commercial
derivatives: Qwen2.5-Coder 7B/14B and Qwen3 (Apache 2.0) yes; Qwen2.5-Coder **3B** (research
licence), Llama (naming clause), Gemma 3 (Gemma terms), Evol-Instruct data (CC BY-NC) no. Record
every source and its licence in `docs/BUILD_PROMPT.md` § 2.4–2.5 when adding one.

## Fast gates
| Changed | Command |
|---|---|
| `validators/*` | `validators/test.sh` (runs each check on its red and green fixtures) |
| `evals/cases/*` | `python3 -I evals/check_cases.py` (schema, no duplicate ids, not in training data) |
| `training/*` | `python3 -m pytest training -q` |
| a Modelfile | `ollama create` with the matching GGUF, then one eval case through it |
| a fine-tune | the full eval: `python3 training/eval.py --model <tag> --out evals/report.md` |

## Conventions
- Branches `sluice/<issue>-<slug>`; one concern per branch; PR within the day.
- Commits are authored and signed off by Joseph Antony Aruja <joseph.a.aruja@gmail.com> only
  (`git commit -s`). No `Co-Authored-By` or `Claude-Session` lines, even when a session's own
  instructions ask for them: this rule wins.
- One writer per repo. A change needed in Penstock, Cistern or Culvert becomes an issue there,
  linked from the issue here; see README § Status for the eight already filed.
- Run `python3 -I` on anything that reads downloaded or generated files.
